# v0.55 Product-Parity Execution Plan

Status: implementation complete. PR [#122](https://github.com/MCprotein/rolling-potato/pull/122)
passed exact-head candidate CI and was merged into `main`; release publication remains
governed by the separate `release/v0.55.0` process.

## Objective

Make the default `rpotato` terminal experience reliable across the complete
user journey instead of declaring completion from isolated adapters and fake
sidecars. Codex, Claude Code, and OpenCode are behavioral references for
interaction concepts; `rpotato` keeps its local-first, small-model runtime and
does not copy their code or claim feature parity without evidence.

## Acceptance Journeys

1. Preserve identity, corrections, exact prior actions, and web evidence across
   follow-up turns and `/resume` without replaying uncertain work.
2. Let the model select bounded web research when fresh public evidence is
   required, then execute visible Search -> Open -> Find -> Answer phases.
3. Show the active request phase and elapsed time, and make cancellation affect
   the active conversation request rather than only a workflow record.
4. Render long Markdown answers, links, tables, nested lists, and code without
   leaking raw syntax or losing scroll/composer state.
5. Treat pasted files, cached model artifacts, and lazy vision projectors as
   distinct states with actionable recovery messages.
6. Prove the default terminal path through deterministic native-terminal tests
   and a separately opt-in managed real-model smoke.

## Ownership Boundaries

- `runtime_core`: typed request activity, cancellation, and bounded tool-loop
  policy. It owns no terminal rendering or network transport.
- `app/tui_adapter`: conversation orchestration, durable activity evidence, and
  conversion between runtime events and presentation-neutral progress.
- `app/web_search_adapter`: bounded Search/Open/Find research sessions and
  evidence selection. It does not decide terminal layout.
- `surfaces/tui`: composer, progress, Markdown, scroll, and user-facing recovery.
- tests: user-journey assertions must cross the same boundaries as production;
  fake-sidecar tests may prove protocol determinism but not model quality.

## Delivery Slices

1. Lock the missing journeys with deterministic regression tests.
2. Add phase-aware request observation and active cancellation.
3. Replace single-shot brittle web routing with a bounded runtime-owned research
   loop and model-generated typed steps, retaining deterministic recovery only
   for malformed small-model output.
4. Persist typed tool activity needed for exact follow-ups and resume.
5. Expand terminal Markdown and long-output interaction.
6. Add native-terminal parity journeys and an opt-in real-model smoke fixture.
7. Reconcile capability documentation with measured behavior.

## Verification

- Run changed-module unit and integration tests after each slice.
- Exercise attached native-terminal journeys for conversation, web, progress,
  cancellation, attachment, model cache, Markdown, and scroll.
- Run one bounded independent review after the scope stabilizes.
- Run the PR candidate preflight once for the final candidate; full test, clippy,
  build, and release policy remain CI-owned for that exact HEAD.

## Candidate Evidence

- Memory and resume: typed tool activity is persisted and restored by
  `session_memory`, with native-terminal coverage proving that prior web work is
  supplied to a resumed conversation without replay.
- Web research: structured model decisions enter the bounded research session,
  which reports Search, Open, Find, and Answer progress and records typed source
  evidence. Cancellation and step/time budgets are enforced at the same
  application boundary.
- Active interaction: the terminal shows phase and elapsed time, and Ctrl+C
  cancels the active generation while keeping the session usable.
- Presentation: Markdown rendering and native-terminal scroll tests cover links,
  tables, nested lists, code, long output, and composer preservation.
- Attachments and models: pending attachments survive failed requests and can be
  cleared explicitly; model cache state and lazy projector readiness remain
  distinct in selection and backend status.
- Runtime proof: deterministic native-terminal journeys remain the default gate;
  `scripts/ci/verify-managed-real-model-smoke.sh` is the opt-in managed-model
  check and validates the configured model context instead of a product cap.

The single bounded independent review is complete. Its findings were closed by
preserving valid structured model decisions, persisting ordered research traces,
bounding network workers, and verifying active projector bindings. The
candidate preflight and PR CI completed for exact candidate HEAD
`e16ced5cfae02612f4ef56ffa45b2869a60b0caa` before the squash merge.

## Stop Conditions

Do not call v0.55 product-ready when any acceptance journey is covered only by
a mock that bypasses the production route, when active cancellation cannot
interrupt the request, or when documentation claims behavior not proven by the
candidate evidence.
