# v0.55 제품 완성도 실행 계획

상태: `feature/v0.55.0-product-parity`에서 구현 중인 계획입니다.

## 목표

분리된 adapter와 fake sidecar가 통과했다는 이유만으로 완료를 선언하지
않고, 기본 `rpotato` 터미널 사용자 여정 전체를 신뢰할 수 있게 만듭니다.
Codex, Claude Code, OpenCode는 상호작용 개념을 비교하는 기준이며, 코드를
복사하거나 근거 없이 동등한 기능을 주장하지 않습니다. `rpotato`의
local-first 소형 모델 runtime은 유지합니다.

## 수용 사용자 여정

1. 이름, 사용자 교정, 직전 작업, 웹 근거를 후속 질문과 `/resume`에서
   기억하되 불확실한 작업을 다시 실행하지 않습니다.
2. 최신 공개 근거가 필요하면 모델이 제한된 웹 조사를 선택하고 runtime이
   Search -> Open -> Find -> Answer 단계를 사용자에게 보여주며 실행합니다.
3. 활성 요청 단계와 경과 시간을 표시하고, 취소가 workflow 기록뿐 아니라
   현재 대화 요청에도 적용됩니다.
4. 긴 Markdown 답변, 링크, 표, 중첩 목록, 코드를 원시 문법 노출이나
   scroll/composer 상태 손실 없이 표시합니다.
5. 붙여넣은 파일, cache된 모델 artifact, 지연 준비되는 vision projector를
   서로 다른 상태로 다루고 복구 방법을 안내합니다.
6. 기본 터미널 경로를 deterministic native-terminal 테스트로 증명하고,
   별도의 opt-in managed real-model smoke를 제공합니다.

## 책임 경계

- `runtime_core`: typed request activity, 취소, 제한된 tool-loop 정책을
  소유하며 터미널 표현이나 네트워크 transport는 소유하지 않습니다.
- `app/tui_adapter`: 대화 orchestration, durable activity evidence, runtime
  event를 표현 중립적인 progress로 변환하는 책임을 가집니다.
- `app/web_search_adapter`: 제한된 Search/Open/Find research session과 근거
  선정을 소유하며 터미널 layout을 결정하지 않습니다.
- `surfaces/tui`: composer, progress, Markdown, scroll, 사용자 복구 안내를
  소유합니다.
- 테스트: 사용자 여정은 production과 같은 경계를 통과해야 합니다.
  fake sidecar는 protocol 결정성을 증명할 수 있지만 모델 품질은 증명하지
  못합니다.

## 구현 단위

1. 누락된 사용자 여정을 deterministic 회귀 테스트로 고정합니다.
2. 단계별 요청 관찰과 활성 요청 취소를 추가합니다.
3. 단발성 웹 routing을 runtime 소유의 제한된 research loop와 typed model
   step으로 바꾸고, 소형 모델 출력이 잘못된 경우에만 deterministic 복구를
   사용합니다.
4. 정확한 후속 질문과 resume에 필요한 typed tool activity를 저장합니다.
5. 터미널 Markdown과 긴 출력 상호작용을 확장합니다.
6. native-terminal parity 여정과 opt-in real-model smoke fixture를 추가합니다.
7. capability 문서를 실제 측정된 동작과 일치시킵니다.

## 검증

- 각 단위 후 변경 모듈 unit/integration 테스트만 실행합니다.
- attached native-terminal에서 대화, 웹, 진행 상태, 취소, 첨부, 모델 cache,
  Markdown, scroll 여정을 검증합니다.
- 범위가 안정된 뒤 제한된 독립 리뷰를 한 번 실행합니다.
- 최종 candidate에서 PR preflight를 한 번만 실행하며 전체 test, clippy,
  build, release policy는 동일 HEAD의 CI가 담당합니다.

## Candidate 근거

- 메모리와 resume: `session_memory`가 typed tool activity를 저장·복원하고,
  native-terminal 테스트가 이전 웹 작업을 다시 실행하지 않으면서 재개한
  대화에 근거를 공급하는지 검증합니다.
- 웹 조사: 구조화된 모델 판단이 제한된 research session으로 진입하고,
  Search, Open, Find, Answer 진행 상태와 typed source evidence를 기록합니다.
  취소와 단계·시간 예산도 같은 application 경계에서 강제합니다.
- 활성 상호작용: 터미널이 단계와 경과 시간을 표시하며 Ctrl+C가 활성
  generation을 취소한 뒤에도 session을 계속 사용할 수 있습니다.
- 표현: Markdown renderer와 native-terminal scroll 테스트가 링크, 표,
  중첩 목록, 코드, 긴 출력, composer 보존을 검증합니다.
- 첨부와 모델: 실패한 요청의 첨부는 유지하고 명시적으로 비울 수 있으며,
  모델 cache 상태와 lazy projector 준비 상태를 선택 화면과 backend 상태에서
  구분합니다.
- runtime 증거: deterministic native-terminal 여정을 기본 gate로 유지하고,
  opt-in `scripts/ci/verify-managed-real-model-smoke.sh`는 제품 고정 상한이 아닌
  선택 모델의 context로 실제 managed model 경로를 검증합니다.

한 번의 제한된 독립 리뷰와 최종 candidate preflight가 같은 candidate 범위에서
완료되기 전에는 제품 준비 완료로 표시하지 않습니다.

## 완료 금지 조건

수용 여정이 production route를 우회하는 mock으로만 검증되거나, 활성 취소가
요청을 중단하지 못하거나, candidate 증거 없이 문서가 구현을 주장하면
v0.55를 제품 준비 완료로 표시하지 않습니다.
